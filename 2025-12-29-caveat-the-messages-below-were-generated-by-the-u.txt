  🔥 Critical Concepts You Asked About

  The N+1 Query Problem

  Imagine you fetch 100 assets:
  async list(): Promise<AssetDto[]> {
      const assets = await this.repo.findAll(); // 1 query - fetches 100 assets

      return assets.map(asset => {
          // 🚨 PROBLEM: This calls fileStorage.getUrl() 100 times!
          // If getUrl() does a database lookup, that's 100 MORE queries!
          return AssetDto.fromEntityWithUrl(asset, this.fileStorage);
      });
  }
  // Total: 1 + 100 = 101 queries! (N+1 problem)

  Solution: Batch operations or eager loading
  // ✅ Better: Generate all URLs in one call
  const assets = await this.repo.findAll();
  const urls = await this.fileStorage.getUrls(assets.map(a => a.id)); // 1 query
  return assets.map((asset, i) => AssetDto.fromEntity(asset, urls[i]));
  // Total: 2 queries only!

  ---
  Pagination

  Problem: Database has 10,000 assets. You can't send them all at once!

  Solution: Send data in "pages"
  // Request: GET /assets?page=2&limit=20
  // Returns items 21-40

  async list(query: ListAssetsDto): Promise<AssetDto[]> {
      const skip = (query.page - 1) * query.limit;  // page 2, limit 20 → skip 20
      const take = query.limit;  // take next 20

      return await this.repo.findAll({ skip, take });
  }

  Response format:
  {
    "data": [ /* 20 assets */ ],
    "meta": {
      "page": 2,
      "limit": 20,
      "total": 10000,
      "totalPages": 500
    }
  }

⏺ 🎓 Senior Engineering Concepts: Async Processing Patterns

  Excellent instinct! Understanding these patterns before implementing is exactly how senior engineers think. Let's break down each approach.

  ---
  1️⃣ Message Queues (Bull, RabbitMQ, Redis Queue)

  What Is It?

  A message queue is like a TODO list that lives in a separate service (usually Redis or RabbitMQ). Your app adds tasks to the queue, and worker processes pick them up and execute them.

  [Web Server] → "Process audio for asset-123" → [Queue] → [Worker Process]
       ↓                                                           ↓
   Returns to user                                    Processes audio (takes 5 min)
   immediately                                        Updates database when done

  Visual Flow:

  User uploads file
      ↓
  Controller → UploadAssetUseCase
      ↓
  Save file, create asset record
      ↓
  Add "process-audio" job to queue ← Returns immediately (status: PROCESSING)
      ↓
  [User sees: "Upload successful, processing..."]

  ... Meanwhile, in the background ...

  Worker picks up job from queue
      ↓
  Transcodes audio (3 minutes)
      ↓
  Analyzes BPM/key (1 minute)
      ↓
  Updates asset: markAsReady()
      ↓
  User refreshes page → Sees status: READY

  ---
  Code Example (Bull with Redis):

  Installing:
  npm install @nestjs/bull bull
  npm install @types/bull --save-dev

  Queue Module Setup:
  // app.module.ts
  import { BullModule } from '@nestjs/bull';

  @Module({
    imports: [
      BullModule.forRoot({
        redis: {
          host: 'localhost',
          port: 6379,
        },
      }),
      BullModule.registerQueue({
        name: 'audio-processing',  // Queue name
      }),
    ],
  })
  export class AppModule {}

  Producer (Your Use Case):
  import { InjectQueue } from '@nestjs/bull';
  import { Queue } from 'bull';

  @Injectable()
  export class UploadAssetUseCase {
    constructor(
      @InjectQueue('audio-processing') private audioQueue: Queue,
      // ... other dependencies
    ) {}

    async execute(command: UploadAssetCommand): Promise<Asset> {
      // ... create asset, save file, etc ...

      asset.markAsProcessing();
      await this.assetRepository.save(asset);

      // Add job to queue (non-blocking!)
      await this.audioQueue.add('process-audio', {
        assetId: asset.id,
        filePath: asset.filePath,
      });

      return asset;  // Returns immediately!
    }

  2️⃣ Event Emitters (NestJS EventEmitter)

  What Is It?

  An event emitter is like a notification system within your app. When something happens (e.g., "asset uploaded"), you emit an event, and listeners react to it.

  [Controller] → [UploadUseCase] → Emits "asset.uploaded" event
                                           ↓
                                [Listener 1: Process Audio]
                                [Listener 2: Send Email]
                                [Listener 3: Log to Analytics]

  Key Difference from Queues:
  - Events happen in-memory (same process)
  - If server crashes, events are lost
  - Synchronous by default (blocks) unless you use @OnEvent({ async: true })

  3️⃣ Cron Jobs (Scheduled Tasks)

  What Is It?

  A cron job runs code on a schedule (every minute, every hour, etc.). Instead of processing immediately when uploaded, you create "pending" records and a cron job picks them up periodically.

  Every 1 minute:
    ↓
  Cron job runs
    ↓
  Find all assets with status = PROCESSING
    ↓
  Process each one
    ↓
  Update status to READY or FAILED

  import type { IAssetRepository } from "../interfaces/asset-repository.interface";
  import type { IAudioProcessingInterface, TranscodeOptions } from "../interfaces/audio-processing.interface";
  import type { IFileStorageService } from "../interfaces/file-storage.interface";

  @Injectable()
  export class ProcessAssetUseCase {
      constructor(
          private readonly assetRepository: IAssetRepository,
          private readonly audioProcessingService: IAudioProcessingInterface,  // ← Fixed name
          private readonly storageService: IFileStorageService,
      ) {}

      async execute(assetId: string): Promise<void> {
          const asset = await this.assetRepository.findById(assetId);

          if (!asset) {
              throw new Error(`Asset not found: ${assetId}`);  // ← Better message
          }

          try {
              const inputPath = asset.filePath;

              // Check if already MP3 (better extension check)
              const fileExtension = inputPath.split('.').pop()?.toLowerCase();

              if (fileExtension === 'mp3') {
                  // Already MP3, skip transcode but still analyze!
                  const analysisResult = await this.audioProcessingService.analyze(inputPath);
                  asset.markAsReady(
                      inputPath,  // Use original as transcoded
                      analysisResult.bpm,
                      analysisResult.key,
                  );
                  await this.assetRepository.save(asset);
                  return;
              }

              // Generate clean output path
              const outputPath = `transcoded/${asset.ownerId}/${asset.id}.mp3`;

              const transcodeOptions: TranscodeOptions = {
                  targetFormat: "mp3",
                  bitrate: 128000,
                  sampleRate: 44100,
              };

              await this.audioProcessingService.transcode(inputPath, outputPath, transcodeOptions);

              const analysisResult = await this.audioProcessingService.analyze(inputPath);

              asset.markAsReady(
                  outputPath,
                  analysisResult.bpm,
                  analysisResult.key,
              );

              await this.assetRepository.save(asset);

          } catch (error) {
              asset.markAsFailed();
              await this.assetRepository.save(asset);

          }
      }
  }
